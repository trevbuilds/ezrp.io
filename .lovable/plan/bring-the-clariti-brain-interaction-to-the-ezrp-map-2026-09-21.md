# Reframe the EZRP knowledge map

## Goal
Make the map communicate the operating model clearly: EZRP at the centre, business domains around it, value streams within each domain, then the guides and detailed topics beyond them.

## Changes
- Replace the current module-first rings with four explicit levels: **EZRP → business domain → value stream → guide topics**.
- Group related value streams into domain clusters so Customer, Finance, People, Asset, and Supply Chain read as coherent areas.
- Treat governance, integration, security, data, project delivery, PMO, and go-live material as cross-cutting capabilities rather than ordinary domains.
- Place cross-cutting capabilities in a distinct shared band and draw secondary links to every relevant domain or stream, avoiding duplicate topic nodes.
- Keep branch highlighting, navigation, panning, zooming, and the existing EZRP visual identity.
- Update the map’s labels and selected-item context so each level is understandable.

## Technical details
- Derive the domain and value-stream nodes from the existing typed guide metadata.
- Add a small explicit relationship map for cross-cutting capabilities where hierarchy alone cannot express many-to-many links.
- Keep the content taxonomy and guide pages unchanged; this is a map presentation and relationship change only.
- Verify desktop and mobile layouts, links, interactions, console health, and the project build.
