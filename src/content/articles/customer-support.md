## Why it matters in an ERP context

Support inside the ERP can draw on everything the system already knows — the customer's orders, their history, what they were shipped and when. That is the difference between a personalised answer and asking the customer to explain their own account back to you.

## The workflow

```steps
Inquiry initiation :: A customer makes contact through one of the available channels.
Ticket generation :: The system raises a support ticket and logs the detail of the inquiry.
Assignment and notification :: The ticket is assigned to a representative, who is notified of the new case.
Issue resolution :: The representative draws on ERP data to resolve it, involving other departments where needed.
Follow-up and feedback :: The customer is contacted for feedback once resolved, and it is logged against the record.
```

> The DX Guides wiki carried the Sales Force Automation workflow on this page. Support is not a sales process: it begins with a case and ends with a resolution, and modelling it as a pipeline produces the wrong metrics and the wrong queue behaviour.

## What you need in place

- **Multi-channel integration**: Email, phone, live chat and self-service portals all landing in the same queue.
- **Customer data management**: Centralised customer data so a representative is not searching three systems mid-call.
- **Knowledge base management**: A maintained repository of answers, for both self-service and agent use.
- **Ticket management**: Tracking, assignment and escalation that someone actually owns.
- **Feedback and reporting**: Tools for collecting feedback and reporting on support performance.

## Implementing it

```steps
Define the support process :: Map it end to end, from inquiry through resolution to feedback.
Select and customise modules :: Choose the modules that support service operations and configure them to the mapped process.
Integrate communication channels :: Bring every channel into one support experience.
Train support staff :: On the system and on the procedures around it.
Deploy the knowledge base :: Make it accessible to customers and staff alike.
Implement feedback mechanisms :: Set up collection and analysis of customer feedback.
```

## Questions to ask vendors

```qa
Channels :: How does the system integrate with different communication channels? :: Confirm which channels are native and which need middleware.
Ticketing :: What features exist for ticket management and tracking? :: Check escalation, SLA handling and queue routing against real scenarios.
Reporting :: Can the system report on support performance? :: Ask to see the standard reports rather than a report builder.
Knowledge base :: What tools exist for knowledge base management? :: Establish who can author and approve articles, and how stale content is found.
```

## Metrics and KPIs to track

```metrics
First response time :: Time taken to acknowledge an inquiry.
Resolution time :: Average time to resolve an issue.
Customer satisfaction (CSAT) :: Customer rating of the support received.
Ticket volume trends :: How ticket numbers move over time, and why.
Self-service usage :: How far customers resolve their own issues through the knowledge base.
```
