## Why it matters

A system that is live but not adopted has cost everything and returned nothing. Adoption is not a training problem; it is a design, leadership and measurement problem that training supports.

- **Benefits depend on behaviour**: The business case assumed people work differently. Nothing else delivers that.
- **Capacity is finite**: An organisation can absorb only so much change at once, and exceeding it produces regression rather than progress.
- **It is a leading indicator**: Adoption signals appear before benefits do, which makes them the early warning.

## The workflow

```steps
Impact assessment :: Who is affected, how their work changes, and what they lose.
Stakeholder mapping :: Influence, impact and what each group needs to hear.
Readiness baseline :: Current ability and willingness, measured rather than assumed.
Leader activation :: Sponsors and managers visibly doing the new thing first.
Learning pathway :: Sequenced so capability arrives just before it is needed.
Adoption measurement :: Actual usage and behaviour tracked after go-live.
Sustainment :: Checked months later, when the programme team has gone.
```

> The strongest predictor of adoption is whether the person's own manager uses the system. Communications campaigns do not compensate for a manager who keeps the old spreadsheet.

## What you need in place

- **A named benefit owner**: Operational, still accountable twelve months after go-live.
- **Impact assessed per role**: Generic change plans produce generic results.
- **Manager enablement**: Before the workforce, not alongside it.
- **Adoption measures defined before go-live**: Usage, exception volume, workaround prevalence.
- **Change capacity view**: What else is landing on the same people at the same time.

## Questions to ask

```qa
Sponsor behaviour :: Are leaders visibly using it? :: If not, no amount of communication will land.
Impact :: Do we know, by role, what changes? :: Without this, training is generic and adoption is accidental.
Measurement :: What will we measure after go-live, and from when? :: Decide before, because afterwards there is no baseline.
Capacity :: What else is hitting these people this quarter? :: Change capacity is the constraint, not budget.
Sustainment :: Who checks in six months? :: Usually nobody, which is when reversion happens.
```

## Metrics and KPIs to track

```metrics
Adoption rate :: Share of target users actually using the new process.
Workaround prevalence :: Old-path usage still occurring.
Manager engagement :: Leaders completing their own enablement.
Support volume :: Queries per user, trending down or not.
Benefit realisation :: Measured against the case, twelve months out.
```
