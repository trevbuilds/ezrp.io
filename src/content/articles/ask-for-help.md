## Why it matters

Every recovered programme has the same forensic finding: the issue that sank the schedule was visible to someone months before it was raised. The question is never why nobody knew. It is why nobody said.

- **Cost compounds with delay**: A design problem found in workshop is a conversation; found in testing it is rework; found at cutover it is the date.
- **Silence is rational when raising is punished**: If the first person who escalated was blamed, nobody else will.
- **Status becomes fiction**: A programme where nothing is ever red is not a healthy programme.

## Putting it into practice

```steps
Make raising cheap :: A low-ceremony route that does not require a paper, a forum or a confrontation.
Respond to the first one well :: The treatment of the first escalation sets the behaviour for the rest.
Separate the problem from the person :: The issue is about the work, and it is discussed that way.
Give it a service level :: Raised issues get a response in a defined time, or people stop raising them.
Close the loop :: The person who raised it is told what happened.
Watch the leading indicators :: All-green status and zero escalations from a large workstream are warnings.
```

> A programme with no red items and a slipping date does not have a reporting problem. It has a truth problem, and the reporting is the symptom.

## What you need in place

- **A route that is not the line management chain**: Some problems are about the chain.
- **Response service levels**: Raised issues acknowledged and actioned in a defined time.
- **Visible response**: People need to see that raising something worked.
- **Independent assurance**: Someone whose role is to find what is not being said.
- **Leaders who raise their own problems**: Behaviour is set from the top, not from the policy.

## Questions to ask

```qa
First escalation :: What happened to the last person who raised something unwelcome? :: Everyone in the programme already knows the answer.
Route :: How does someone raise a concern without going through their manager? :: If there is no route, some concerns will not be raised.
Latency :: How long between a problem being known and being reported? :: Ask the team, not the register.
Status :: Is anything red, and has it ever been? :: Perpetual green in a complex programme is not good news.
Response :: What service level applies to a raised issue? :: Unanswered escalations train people not to escalate.
```

## Metrics and KPIs to track

```metrics
Issue age at raise :: Known to reported, sampled by asking.
Escalation volume :: By workstream — silence from a large one is a signal.
Response time :: Raised to acknowledged and actioned.
Status distribution :: Red, amber and green over time.
Late surprises :: Issues first reported within a month of a gate.
```
